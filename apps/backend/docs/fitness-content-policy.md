# MYPA Fitness Content Policy

## Release gate

A fitness discipline is considered **content-complete** only when all of the following are true:

- at least 500 published movements exist for the discipline;
- movements are distributed across the 1–10 progression scale;
- every published movement has at least 4 approved, distinct WebP media assets;
- every movement has step-by-step instructions and safety/coach cues;
- every record has a source provider, source URL, license and attribution metadata where required;
- no non-commercial-only source is used in production;
- the import audit passes without exceptions.

The API deliberately exposes `mediaActual`, `mediaRequired` and `mediaComplete` so incomplete assets cannot silently look complete in the app.

## Approved source strategy

### RepDB free distribution

RepDB currently publishes a free exercise catalog with hundreds of illustrated exercises in flat WebP and explicitly allows personal/commercial in-app use with attribution. The raw dataset must not be redistributed as a standalone dataset. The importer records RepDB attribution and keeps it as a product content source.

### Free Exercise DB

Free Exercise DB is an open public-domain exercise dataset with 800+ exercises and associated imagery. It is used as a supplement for movement coverage and is not treated as the sole source of visual assets.

### Wikimedia Commons

For missing visual coverage, the importer may query Wikimedia Commons and accept only images whose returned license metadata is compatible with commercial product use, such as CC0, public domain, CC BY or CC BY-SA. Attribution is retained in the media row.

### Explicitly excluded

Do not import Yoga-82 or other sources with non-commercial/research-only terms into the production catalog unless the exact asset license is separately verified for commercial app use.

Do not use ExerciseDB/GymVisual or scraped copyrighted exercise image sets without a commercial redistribution license.

## Yoga quantity policy

Yoga is a special case. A raw list of asana names is not enough to honestly claim 500 distinct movements. Where a source does not provide 500 uniquely illustrated, independently documented asanas, the importer may create **explicitly named technique/variation records** only when the variation has its own instructions and progression meaning. These records remain distinguishable from canonical asanas via `variantKind` and `parentExerciseId`.

The release gate counts only published records, and the content team should prefer canonical movements over cosmetic renaming.

## WebP policy

All production media exposed by the fitness API is required to be `format=webp` and `status=approved`. Source images may be JPG/PNG, but the importer stores a WebP delivery URL generated by the configured image transformation pipeline. A future storage migration can replace these delivery URLs with durable Supabase/CDN objects without changing the API contract.

## Operational workflow

1. Apply the fitness content migration.
2. Run `pnpm fitness:content:import` against the intended content database.
3. Run `pnpm fitness:content:audit`.
4. Do not promote a discipline until the audit passes.
5. Re-run the audit whenever source assets or licenses are changed.
